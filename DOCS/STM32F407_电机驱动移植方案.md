## 0. 结论先行

### 0.1 能直接复用 / 必须重写

| 现有资产 | 移植方式 | 说明 |
|---|---|---|
| `protocol.hpp` 帧编解码、量程、参数 ID | **逐行翻成 C**（~400 行） | 无任何 ROS 依赖，是整份代码里最值钱、最该原样保留的部分 |
| `set_zero.cpp` 归零序列 | **照抄写零/失能/回读流程** | 类型 6 自带持久化；必须先失能；回读验证；不要顺手写类型 22；写零后 raw=0，不需要 offset |
| `hold_controller` 拖动控制律、激活斜坡、钳位 | **照抄逻辑** | 去掉 ROS 接口，保留 Kp=0 / Kd / τ_ff 的安全语义 |
| `gravity_compensator` 的重力模型 | **离线生成 C 表 + 手写 FK** | 不搬 pinocchio；已用原型验证公式（见 4.6） |
| `lite_driver_system` 的 direction / homing_offset / 2π 折叠 / 夹爪换算 | **只保留 direction** | 录制/回放/归零全用 raw，不需要 offset/2π/夹爪换算；direction 只给重力补偿用 |
| `calibration.yaml` / `joint_spec.yaml` | 生成 `robot_config.c/h` | 只取 CAN ID、型号、力矩/速度上限、direction；**不做运行期标定表导入** |
| `inertia_params.yaml` + `lite_arm_model.urdf` | 离线生成 `gravity_model_*.c/h` | 标定参数成对使用（mass + first_moment） |
| `test_protocol.cpp` 的协议向量 | 改成主机侧 C 单测 | 保证 MCU 编出来的帧和 ROS 逐字节一致 |
| ROS2 control / SocketCAN / pinocchio / yaml-cpp / Eigen | **不移植** | MCU 上没有这些运行时 |

### 0.2 三个关键结论

1. **协议层可以直接搬到 MCU。** 帧长 8 字节、29 位扩展 ID、1 Mbps，
   每路 8 台电机 100 Hz 命令 + 100 Hz 应答，总线负载约 20~25%，F407 完全够。
2. **重力补偿不需要 pinocchio。** 只需要“正运动学 + 重力矩”：
   `τ_i = -Σ_j m_j · g · (z_i × (p_com_j - p_i))`。
   我用本工作区的 URDF + 标定参数做了原型验证（`docs/prototype_gravity_check.py`），
   与 `pinocchio::rnea(q,0,0)` 在 20 组随机位形上**最大误差 1.5e-14 N·m**，
   最大力矩 5.77 N·m。C 版用 float 实现即可，每周期不到 10 µs。
3. **归零是“换臂保护”，不是录制/回放的前置计算。** 录制/回放只依赖
   电机 raw 位置，单臂内的零点漂移/offset 不影响录制与回放的逻辑；
   起点一致性由 **±15° 姿态门禁**保证。归零只用于同一块板子换到另一条
   机械臂时**统一零点**，防止两边初始零点差太大、使能瞬间冲向零位（“起飞”）。

### 0.4 已确认决策（v1.0）

| 项 | 决策 | 影响 |
|---|---|---|
| 坐标空间 | **录制/回放/归零/门禁全部用电机 raw 位置** | 不需要 homing_offset、限位、夹爪端点；见 1.2 / 4.9 |

| 无夹爪方案 | **暂时只做 16 轴方案**；无夹爪不单独标定重力参数 | 探测到 14 轴时只允许基础控制，**重力补偿默认关闭**；见 4.3 |
| 板子定位 | **完全独立运行**，不接 ROS | 不加 USB CDC/以太网桥；保留调试串口；见 3.1 |
| 调度方式 | **裸机 + 1 ms 协作式调度，不用 RTOS** | 模式互斥（录制/回放二选一），无需抢占；见 3.2 |
| UI/按键 | **中文 + 4 键**（上/下/OK/BACK） | 4 键导航；字库子集放 W25Q64；见 4.7 |
| 硬件安全 | **硬件急停切断电机动力** | 需接触器/继电器 + 辅助触点；注意断电后机械臂可能因重力下落；见 2.5 / 4.12 |

## 1. 现有驱动到底做了什么（移植时必须对齐的语义）

### 1.1 协议与模式

- 29 位扩展 ID：`[28:24] comm_type | [23:8] extra_data | [7:0] device_id`。
- MIT 帧：`id = type 1 | torque_raw << 8 | device_id`，payload 是
  `pos | vel | kp | kd` 四个大端 u16；力矩塞在 ID 的 `extra_data` 里。
- 反馈：类型 2（对每条命令 1:1 应答）与类型 24（主动上报）布局相同；
  温度 `raw × 0.1 °C`，故障位在 `extra_data` 高 6 位。
- 状态帧位置/速度/力矩的编码**与型号无关**：位置恒为 ±4π。
- 参数（类型 18 写、17 读）：
  `run_mode 0x7005`、`torque_limit 0x700B`、`loc_ref 0x7016`、
  `limit_spd 0x7017`、`limit_cur 0x7018`、`acc_rad 0x7022`、`zero_sta 0x7029`。
- 运行模式：MIT 组 `0=零力矩 / 1=HOLD / 2=TRACKING`；
  CSP 组 `5=监视 / 6=HOLD / 7=TRACKING`。
- **跨组（MIT↔CSP）在 ROS 驱动里是启动参数，运行期不允许切换。**
  板子要实现切换，必须自己做“失能 → 写 run_mode → 重新使能”的安全序列，
  这是本方案相对现有驱动的**新增行为**，需要单独验证。

### 1.2 坐标空间：录制/回放只用 raw

**本板不发布 URDF 关节角，也不做限位映射，所以不需要那套标定表。**

电机侧的位置本来就是 raw（rad）：

- 类型 2 反馈的 `position` 是电机原始位置；
- CSP 的 `loc_ref` 是 raw 位置；
- MIT 帧的 `position` 也是 raw 位置。

因此：

```text
录制：直接存 raw[16]（16 台电机）
回放：直接把 raw[16] 写进 CSP loc_ref
门禁：直接判 |raw| ≤ 15°
归零：写类型 6，让参考姿态下 raw = 0
```

**不需要**：`homing_offset`、`2π` 折叠、关节限位、夹爪 `closed/open` 端点、
方向翻转。这些是 ROS 侧为了发布 URDF 关节角和做限位保护才需要的；
本板只做“记录 raw → 回放 raw”，整条链路是同一坐标空间。

#### 唯一例外：重力补偿

重力模型是在 URDF 关节角 `q` 下辨识的，所以 **只有重力补偿** 需要把 raw
换成 `q`。归零后参考姿态 raw=0、q=0，于是：

```text
q_i = direction_i × raw_i        // direction = ±1，16 个常数
```

- `direction` 从现有 `calibration.yaml` / `joint_spec.yaml` 抄成 16 个 ±1，
  **固化在固件里**，不是运行期导入的标定表。
- 如果不需要重力补偿，`direction` 也可以完全去掉，整个固件只剩 raw。
- 重力前馈的常数偏置 `offsets_nm` 仍然保留在重力参数里，它不属于关节映射。

> 夹爪：raw 直接录制/回放，不需要开度（米/百分比）换算。
> UI 想显示“开度百分比”时可以按 raw 的行程范围算，但这只是显示，不参与控制。

### 1.3 MIT 与 CSP 的真实差别

| | MIT | CSP |
|---|---|---|
| 主机发什么 | pos/vel/Kp/Kd/τ_ff（每拍） | 只发 `loc_ref` |
| 谁算力矩 | 主机 | 电机固件的位置/速度/电流环 |
| 能否松劲 | 能（全 0 / Kp=0） | **不能**；写 0 = 命令回零点 |
| 力矩上限 | 软件钳 τ + 型号量程 | 只能写 `limit_cur` |
| 通信断了 | 保持上一帧（可能一直出力） | 停在最后目标位 |
| 刚度 | Kp 可调 | 固件 `loc_kp`，本项目不写 |

### 1.4 必须继承的“踩坑清单”

1. **CSP 的 `limit_cur` 是峰值 Apk**，由扭矩折算必须 `÷kt × √2`；
   漏 √2 实际力矩只有 70.7%。
2. **类型 18 写入掉电丢失**；类型 22 会把“当前所有可存储变量”一起固化
   （包括残留的 `run_mode=5`）。本方案**不主动写电机 flash**，参数每次上电重写。
3. **归零前必须失能**，否则固件静默忽略写零帧。
4. **类型 24 的使能字节在 `data[6]`**，不是 `data[0]`。
5. **夹爪不参与重力前馈**（标定没辨识夹爪；强行算会得到 7~10 N·m 垃圾）。
6. **MIT 没有“最大速度”寄存器**，只能在主机侧钳 `v_des`；
   `limit_spd` 是 CSP 的参数。
7. **HOLD 激活必须做斜坡**：Kp 一步跳变 + 位置目标残留 0 = 满力矩冲向零点。
8. **位置读不到时绝不能拿 0 当目标**（尤其是高 Kp HOLD），应退化为全 0 松劲。

## 2. 目标硬件

### 2.1 芯片资源

| 项 | STM32F407VET6 | 本方案占用 |
|---|---|---|
| 内核 | Cortex-M4F 168 MHz，单精度 FPU | 够用（重力/三角/滤波） |
| Flash | 512 KB | App 约 230 KB（LVGL + HAL + 应用） |
| SRAM | 128 KB + 64 KB CCM | 约 90 KB（见 2.4） |
| CAN | 2× bxCAN | CAN1=左臂，CAN2=右臂 |
| SPI | 3× | SPI1=LCD，SPI2=W25Q64 |
| I2C | 3× | I2C1=24C02 |
| USART | 6× | USART1=调试日志 |

> 初始化时两路都要配滤波器（29 位扩展帧，可先全通），否则 CAN2 收不到。
> 终端电阻 120 Ω 只在总线两端各一个，板上建议留跳线可选接入。

### 2.5 电源、CAN 收发与急停（建议）

- **供电**：12~24 V 输入 → 5 V buck（≥1 A）→ 3.3 V（≥500 mA）。
  F407 小系统板的 3.3 V 稳压器通常较弱，LCD 背光 + 两路收发器建议单独 3.3 V。
- **CAN 收发器**：优先 3.3 V 的 SN65HVD230；要抗干扰可用隔离型 ADM3053
  （需隔离 5 V）。TJA1050 是 5 V 器件，RX 输出要分压/电平转换后才能进 F407。
- **终端电阻**：总线两端各 120 Ω；板上留跳线，默认不焊，按现场决定。
- **共地**：逻辑地与电机电源地单点连接；CAN 用双绞线，屏蔽层单端接地。
- **急停（已确认：硬件切断动力）**：
  - 电机动力（24/48 V）串一个**常闭急停按钮 + 接触器/继电器**；按下急停
    直接断开动力，MCU 的逻辑 5 V/3.3 V **保持供电**。
  - 接触器辅助触点接 `PWR_GOOD`，急停按钮辅助触点接 `ESTOP_IN`，
    MCU 能区分“急停按下”和“动力丢失”。
  - 软件急停作为第二道：检测到 `ESTOP_IN` 后立即发失能帧、停止录制/回放、锁存故障。
  - ⚠️ **断电后机械臂会因重力下落**。如果结构不允许，需要加抱闸，或改成
    “先受控停止、再断动力”的分级急停（安全继电器延时/双通道）。
  - ⚠️ 电机动力断电后电机重启，`run_mode`/`limit_*` 都回默认值；急停恢复后
    必须**重新探测、重写参数、重新使能**，不能直接继续跑。
  - 接触器线圈要加续流二极管；大电容母线建议加预充电阻，避免上电冲击。

## 3. 固件总体架构

### 3.1 分层

```text
┌─────────────────────────────────────────────────────────────┐
│ UI 层        LVGL 页面 / 菜单 / 按键事件 / 蜂鸣器反馈          │
├─────────────────────────────────────────────────────────────┤
│ 应用层       模式状态机 app_state                            │
│              MIT 模式 / CSP 模式 / 录制 / 回放 / 归零 / 设置   │
├─────────────────────────────────────────────────────────────┤
│ 控制层       mit_ctrl / csp_ctrl / gravity / safety          │
│              （100 Hz，纯计算，不碰 HAL）                     │
├─────────────────────────────────────────────────────────────┤
│ 电机层       joint_map / motor_mgr / rs_protocol / can_bus   │
│              （帧编解码、队列、超时、故障）                    │
├─────────────────────────────────────────────────────────────┤
│ BSP 层       st7789 / w25q64 / at24c02 / keys / buzzer / adc │
├─────────────────────────────────────────────────────────────┤
│ HAL/CMSIS    STM32F4xx HAL + LVGL + 1 ms 协作式调度           │
└─────────────────────────────────────────────────────────────┘
```

控制层**不直接调用 HAL**，只通过 `motor_mgr` 的接口下发指令；
这样协议/控制逻辑可以在 PC 上做单元测试。

### 3.2 为什么不用 RTOS（结论：不需要）

你的判断是对的：**模式是互斥的**——同一时间只可能是“拖动/录制/回放/菜单”
中的一个，不存在需要并行推进的长任务。具体理由：

| 理由 | 说明 |
|---|---|
| 模式互斥 | 录制和回放二选一；UI 只是状态展示，不参与实时控制 |
| 唯一异步源 | CAN 接收、LCD DMA 完成都用中断 + 环/标志，主循环轮询即可 |
| 100 Hz 很宽松 | 控制最坏工作量约 2~3 ms，10 ms 周期余量充足 |
| 没有阻塞等待 | CAN 用环 + 邮箱；LCD 用 DMA；W25Q64 的擦/写是**芯片内部异步**，发完命令就返回；EEPROM 只在设置页写 |
| 故障模式更少 | 没有优先级反转、互斥锁、栈溢出、任务饿死 |
| 调试更简单 | 单栈、单主循环、逻辑顺序固定，示波器/断点友好 |
| 以后要加也能加 | 模块边界已经按“可测试”切好，真要上 FreeRTOS 只需把 slot 换成任务 |

**结论**：裸机 + 1 ms 协作式调度即可，不引入 FreeRTOS。
唯一要守住的纪律是：**主循环里任何一步都不能长时间忙等**。

### 3.3 1 ms 协作式调度

SysTick 每 1 ms 置位一次；主循环按固定顺序处理标志，处理完就返回，
不在一处死等：

```c
for (;;) {
  if (tick_10ms) { tick_10ms = 0; control_slot(); }   // 最高优先，先做
  can_rx_drain();          // 每次最多 N 帧，剩下的下一圈
  storage_slice();         // W25Q64 状态机，一次只推进一步
  ui_slice();              // LVGL 定时器/脏区刷新，一次最多 1~2 ms
  key_scan();              // 20 ms 一次
  monitor_slot();          // 1 s 一次
  __WFI();                 // 空闲休眠，等中断
}
```

| 时间片 | 周期 | 预算 | 职责 |
|---|---|---|---|
| `control_slot` | 10 ms | ≤ 3 ms | 安全判定 → 控制律 → 组帧 → CAN 发送 |
| `can_rx_drain` | 事件/每圈 | ≤ 0.5 ms | 解析反馈、更新关节快照、故障位 |
| `storage_slice` | 每圈 | ≤ 1 ms | 录制落盘、回放预取、flash 状态机 |
| `ui_slice` | 20~33 ms | ≤ 3 ms/次 | LVGL timers + 脏区渲染 + 页面逻辑 |
| `key_scan` | 20 ms | < 0.2 ms | 消抖、长短按 |
| `monitor_slot` | 1 s | < 1 ms | 温度/故障/电压汇总、黑匣子、喂狗 |

调度规则：

- **模式互斥**：`app_state` 每圈只调用当前模式的一个 handler；录制和回放
  不会同时运行，所以没有共享状态的并发问题，也不需要互斥锁。
- **控制优先**：`tick_10ms` 一到，先做控制；其它 slice 都在控制之后。
- 每个 slice 自己限时（例如 UI 一次只处理一个 timer / 一个脏区），
  做不完就留到下一圈，**不能**在 UI 里死循环。
- `control_slot` 里只做纯计算和“入队”，不做 SPI flash、EEPROM、LCD 绘制。
- 记录 `tick_10ms` 的实际周期；抖动 > 2 ms 记录，> 20 ms 触发降级。

### 3.4 中断

| 中断 | 处理 |
|---|---|
| SysTick（1 ms） | `tick++`，置 `tick_10ms` / `tick_20ms` / `tick_1s` 标志 |
| CAN1_RX0 / CAN2_RX0 | 读帧 → 存入 SPSC 环 → 置 `can_rx_pending` |
| CAN1/2_SCE | 错误计数；bus-off 置故障标志 |
| SPI1 DMA TX complete | 置 `lcd_dma_done`，通知 LVGL flush 完成 |
| EXTI0（急停） | 置 `estop_flag`；硬件已切断动力，软件下一圈处理 |
| IWDG | 不需要中断；主循环心跳喂狗 |

中断里只做“搬数据 + 置标志”，**不做解析、不做控制、不发长帧**。
CAN RX 环是单生产者/单消费者，不需要关中断保护（用 head/tail 原子读写）。

### 3.5 非阻塞要点（这套架构成立的前提）

1. **W25Q64 的擦除/写入是异步的**：发 `0x20`/`0x02` 命令后芯片自己忙，
   主机只需下一圈读状态寄存器（`0x05`）看 `BUSY`。**绝不 `while(BUSY)` 死等**。
2. **LCD 用 DMA**：LVGL 的 `flush_cb` 启动 DMA 后立刻返回，完成中断里
   再调 `lv_disp_flush_ready()`。
3. **EEPROM 只在设置页/空闲写**：24C02 写周期约 5 ms，写的时候不要做控制；
   或者写完后置 `eeprom_busy`，下一圈再继续。
4. **CAN 发送用队列 + 节流**：每毫秒最多发 2~3 帧，避免 3 个邮箱被突发撑爆。
5. **主循环禁止 `HAL_Delay`**（初始化除外）；需要延时就记 `tick` 等下一圈。

只要守住这 5 条，10 ms 控制周期不会被 flash/UI 打断。

### 3.6 控制周期数据流

```text
CAN RX 中断 ──► 帧环 ──► can_rx_drain ──► joint_state[]（双缓冲快照）
                                               │
control_slot（10 ms）                          ▼
  1. 读快照 / 检查超时、故障、急停 ──► safety
  2. 模式控制律 ──► cmd[16]（raw pos/vel/kp/kd/tau 或 loc_ref）
  3. 组帧 ──► can_tx 环 ──► 节流发送 ──► CAN1/CAN2
  4. 发布遥测 ──► UI / 黑匣子
```

## 4. 模块设计

### 4.1 协议层 `rs_protocol`

把 `protocol.hpp` 翻成 C，保留所有常量与量化公式：

```c
typedef struct { uint32_t id; uint8_t dlc; uint8_t data[8]; } can_frame_t;

typedef enum {
  RS_GET_ID=0, RS_OP_CTRL=1, RS_OP_STATUS=2, RS_ENABLE=3, RS_DISABLE=4,
  RS_SET_ZERO=6, RS_SET_ID=7, RS_READ_PARAM=17, RS_WRITE_PARAM=18,
  RS_FAULT=21, RS_SAVE=22, RS_SET_BAUD=23, RS_ACTIVE_REPORT=24, RS_SET_PROTO=25
} rs_comm_t;

void rs_encode_mit(can_frame_t*, uint8_t dev, const rs_limits_t*, rs_mit_cmd_t);
void rs_encode_ctrl(can_frame_t*, rs_comm_t, uint8_t dev, uint8_t host,
                    const uint8_t *payload, uint8_t dlc);
void rs_encode_write_f32(can_frame_t*, uint8_t dev, uint8_t host,
                         uint16_t param, float v);
void rs_encode_write_u8(...);
void rs_encode_read(...);
void rs_encode_save(...);
bool rs_decode_status(const can_frame_t*, const rs_limits_t*, rs_status_t*);
bool rs_decode_read(const can_frame_t*, rs_read_reply_t*);
```

必须带：
- 型号量程表（rs-00…rs-06）与 kt 表；
- `csp_limit_current_from_torque(torque, kt)` 内含 **×√2**；
- 主机 ID 默认 `0xFD`；
- 主机侧单测：用 `test_protocol.cpp` 里的期望字节做逐字节比对。

**两路总线同步**：同一控制周期内按“左1/右1/左2/右2…”交替发送，
最大相位差约 0.5~1 ms；不要先发完整左臂再发右臂，否则两臂动作有明显先后。

**不要**在 MCU 上做“按型号自动识别”。型号由 `joint_spec` 静态给出；
`GetDeviceId` 只返回 UID，不返回型号。

### 4.2 电机表 `robot_config`

`robot_config.c` 由脚本从 `joint_spec.yaml` + `calibration.yaml` 生成，
但只保留**静态电机参数**：

```c
typedef struct {
  uint8_t  can_bus;        // 0=CAN1, 1=CAN2
  uint8_t  can_id;
  uint8_t  model;          // RS00..RS06，决定量程/kt
  int8_t   direction;      // ±1，**只给重力补偿**把 raw 换成 URDF q
  float    max_torque;     // N·m, 保护值（max_safe_torque）
  float    max_speed;      // rad/s, MIT 软件钳位 / CSP limit_spd
  float    kp_hold, kd_hold;
  float    limit_spd, acc_rad, limit_cur;
  bool     is_gripper;
} motor_cfg_t;
```

**没有** `homing_offset`、`lower/upper`、`grip_closed/grip_open`。

- 录制/回放/归零/门禁都直接用 `raw`，不调用任何 `joint_from_raw()`。
- 重力补偿用 `q = direction × raw`；不参与重力时 `direction` 可全部设为 +1。
- 位置安全只在**协议量程**上做硬钳位（位置 ±4π、速度/力矩按型号），
  不引入 URDF 关节限位。
- 回放时可选地做“录制数据 min/max”检查（防止槽位数据损坏），
  这不是关节限位表。

### 4.3 电机探测与夹爪方案

上电自检流程：

1. 两条总线分别广播 `GetDeviceId`（类型 0），扫描 1~32；
2. 与 `robot_config` 里期望的 ID 对比：
   - 14 个臂轴必须全部在线，否则进入 `FAULT`，不允许使能；
   - ID 18 / 28 在线 → 判定“含夹爪”；两个都在 → 16 轴方案；
     只有一个 → 弹窗让用户确认“单夹爪/误接”，默认按**不含**处理并告警；
   - 都不在 → 14 轴方案；
3. 记录每台电机的 UID（8 字节），存入配置，便于下次识别“换了电机”；
4. 读取 `run_mode`/故障位（类型 17）做健康检查（可选）。

**不同方案具体差什么：**

| | 14 轴（无夹爪） | 16 轴（含夹爪） |
|---|---|---|
| 方案状态 | **暂不完整支持**（仅探测 + 基础控制） | **当前唯一完整方案** |
| 电机表 | 7+7 | 7+7+1+1 |
| 重力模型 | **关闭重力补偿**（避免用带夹爪参数过补偿） | 现有 `inertia_params.yaml` |
| 夹爪控制 | 不显示 | raw 位置/保持；不参与重力前馈 |
| 回放帧长 | 14 × int16 | 16 × int16 |
| 夹爪零点 | — | **参与整机归零**；raw=0，无端点换算 |

> **决策**：暂时只把 16 轴（含夹爪）作为完整方案。检测到 14 轴时：
> - 允许零力矩/HOLD（HOLD 建议只用小 Kp）；
> - **重力补偿拖动默认禁止**，UI 明确提示“无夹爪重力参数未标定”；
> - 等后续有无夹爪 `inertia_params` 后，再开放 14 轴重力拖动。
>
> 原因：现有重力参数是在**装着夹爪**时辨识的，夹爪连杆的 mass 是非物理值
> （0.53 kg 等），只对“臂关节拟合”有意义。无夹爪时直接沿用会**过补偿**
> （手臂上飘）。见第 8 节 P1。

### 4.4 MIT 控制

控制律（与电机固件一致）：

```text
τ = Kp·(p_des − p) + Kd·(v_des − v) + τ_ff
```

板端三种 MIT 模式：

| 模式 | p_des | v_des | Kp | Kd | τ_ff |
|---|---|---|---|---|---|
| 零力矩拖动 | 0（Kp=0 时无意义） | 0 | 0 | 0 | 0 |
| 重力补偿拖动 | 0 | 0 | **0** | `alpha·Kd_drag` | `alpha·ratio·(ĝ(q)+offset)` |
| 位置保持 | 进档时捕获 raw | 0 | `alpha·Kp` | `alpha·Kd` | 可选 `alpha·τ_ff` |

- **MIT 的 position 字段就是 raw**，HOLD 直接锁当前 raw，不需要任何换算。
- `alpha` 是 0.5 s 激活斜坡（Kp、Kd、τ_ff 同步升起），防止满力矩冲击。
- `Kp=0` 是“零力”的关键：有 Kp 就变成弱弹簧，会被外力持续对消。
- `Kd_drag` 是纯粘滞阻尼，抑制残余力矩导致的匀速漂移；建议 0.3~1.0 起步。
- 每关节 `|τ_ff|` 必须钳到 `max_safe_torque`（肩 7 / yaw 2.5 / 肘 4 /
  腕 1.5~1.8 / 夹爪 0.25 N·m）。
- `v_des` 用 `max_speed` 钳位：**MIT 没有速度寄存器**，这是唯一手段。
- 读不到位置时：HOLD **拒绝激活**；运行中掉线 → 写全 0 松劲，并报故障。

### 4.5 CSP 控制

进入序列（照抄驱动，顺序不能变）：

```text
1. 全部失能（类型 4），等 50 ms
2. 写 run_mode=5（类型 18，逐台，间隔 2~5 ms）
3. 写 limit_spd(0x7017)、acc_rad(0x7022)、limit_cur(0x7018)
4. 全部使能（类型 3），等 50 ms
5. 第一帧 loc_ref 写**当前实测 raw 位置**（不是首帧目标），之后每 10 ms 写目标
```

- **CSP 的 `loc_ref` 就是 raw 位置**；录制的 raw 直接写，不做坐标换算。
- `limit_cur` 来源：`max_safe_torque / kt × √2`（Apk），并钳到型号峰值。
- `limit_spd` / `acc_rad` 来自 `joint_spec`，可由板端设置页修改。
- **CSP 不能“松劲”**：写 0 = 回零点。所以 CSP 只用于 HOLD/回放，
  绝不能用零力矩逻辑。
- 退出 CSP 回 MIT：失能 → 写 `run_mode=0` → 等 100 ms → 按 MIT 模式重新使能
  + 斜坡。
- 参数都是 RAM 的，掉电丢失；每次上电/切换模式必须重写。

### 4.6 重力补偿（板端实现）

#### 4.6.1 模型来源

- 运动学/质量：`lite_arm_model.urdf`
- 辨识参数：`inertia_params.yaml`（mass + first_moment 成对）
- 规则照抄 `gravity_compensator.cpp`：
  - `mass: null` → 取 1.0，`com = first_moment / 1.0`；
  - 每关节加 `offsets_nm`（这是重力模型的常数偏置，不是关节映射的 offset）；
  - 夹爪关节不参与，q 冻结在 0；
  - 输出再按 `max_safe_torque` 钳位。

#### 4.6.2 离线生成

`gen_gravity_model.py` 做三件事：

1. 解析 URDF，得到每臂 7 个转动关节的 `parent→joint` 变换（xyz/rpy）、轴、限位；
2. 把每个连杆的惯性参数写成“在所属关节坐标系下的 mass + com”；
   对最后一个臂关节之后的固定/夹爪/被动/相机连杆，按 q=0 的静态变换
   **合并**成一个末端刚体（因为它们的关节永远不动，合并是精确的）；
3. 生成 `gravity_model_left.c` / `gravity_model_right.c`：

```c
typedef struct { float t[3]; float rpy[3]; float axis[3]; } g_joint_t;
typedef struct { float mass; float com[3]; } g_body_t;
typedef struct {
  uint8_t njoints;
  const g_joint_t *joints;
  const g_body_t  *bodies;   // bodies[i] 属于 joints[i]
} g_model_t;

void gravity_tau(const g_model_t*, const float q[7], float tau[7]);
```

运行时只做 7 次变换 + 7 个“关节→远端质量”求和，单精度即可。

#### 4.6.3 原型验证结果

`docs/prototype_gravity_check.py` 已用真实 URDF + 标定参数验证：

```text
公式：τ_i = -Σ_j m_j · g · (z_i × (p_com_j - p_i))
对照：pinocchio rnea(q,0,0)（mass/first_moment 写回模型）
结果：20 组随机位形，最大误差 1.5e-14 N·m，最大力矩 5.77 N·m
```

这说明“MCU 不做 pinocchio、只做 FK + 重力矩”是可行的，且数学上与现有
ROS 实现等价。C 版用 float 的误差预计 < 1e-4 N·m，远小于摩擦残差。

#### 4.6.4 运行时

```c
for each arm:
  gravity_tau(&model, q_arm, tau_gravity);       // 只需 7 个关节角
  for i: tau_ff[i] = clamp(tau_gravity[i] + offset[i], ±max_safe_torque[i]);
         tau_ff[i] *= ratio;                     // 0~1，调试手感
```

- `q` 由 raw 直接换算：`q_i = direction_i × raw_i`。
  归零后参考姿态 raw=0、q=0；不需要 `homing_offset`/`2π` 折叠。
- 重力方向默认 `(0,0,-9.81)`；若机械臂基座不是水平安装，模型里要旋转重力，
  或生成时把基座安装角写进表（需确认，见 P2）。
- 每拍、每臂计算量 < 10 µs（168 MHz + FPU）。
- 如果最终不做重力补偿，`direction` 表可以整张删掉，固件完全 raw 化。

#### 4.7.1 状态机

### 4.8 归零（需求 4：换臂保护）

#### 4.8.1 定位

归零**不是**录制/回放的前置计算，也不修零点漂移。录制/回放是 raw 对 raw，
同一条臂内部始终自洽。

它只解决一件事：**同一块板子换到另一条机械臂时，两边 raw 零点差太大**，
使能/回放瞬间可能朝零位猛冲（“起飞”）。

做法：

```text
用户自己把机械臂摆到参考姿态
→ 16 台电机（14 臂 + 2 夹爪）全部写类型 6
→ 参考姿态下所有电机 raw = 0
```

写完之后：

- 录制/回放直接用 raw，不需要 offset/限位/夹爪端点；
- 起点门禁直接判 `|raw| ≤ 15°`；
- 换到另一条臂时重复一次，两边读数就统一了。

> **夹爪也参与归零**。夹爪不再需要 `closed/open` 端点；
> 录制/回放直接存 raw、回放 raw，开度换算完全去掉。

#### 4.8.2 前置条件与“参考姿态”

- 16 台电机全部在线、全部失能（未失能时固件会**静默忽略**类型 6）。
- **参考姿态由用户自己摆**，板子不做自动对齐、不做工装检测。
- 写零前屏幕显示 16 个轴的 raw 角度（度），供用户核对当前姿态；
  不要求 raw 在某个范围内（写零前 raw 本来就不是 0）。
- 长按 OK 3 s + 二次确认后才允许写类型 6。
- 写零是**信任操作**：摆错姿态不会报错，只会把所有读数整体平移。
  对同一条臂的录制/回放仍然自洽，但换臂统一和重力补偿会受影响。
- **±15° 门禁只能检查“是否在当前零点附近”，不能检查“零点是否摆对”**；
  零点正确性由操作者负责。建议在机身上给参考姿态做标记/销孔。

#### 4.8.3 执行序列

```text
1. 全部失能（类型 4），等 100 ms
2. 逐台多次读 raw，取中值 → raw_before[]，写入 W25Q64 pending 区（CRC）
3. 关主动上报（类型 24，data[6]=0）—— 若曾开过
4. 逐台发类型 6，data[0]=1，间隔 30 ms（16 台，含夹爪）
5. 用零 MIT 帧回读 raw，每台重复读到 |raw| < 2°（最多 3 次）
6. 清 pending，写 W25Q64 归零记录（日期、UID、raw_before、结果）
7. 不写类型 22、不改 zero_sta
```

- 写零后**不需要提交任何 offset**：关节映射就是 `raw`，参考姿态 raw=0。
- 建议断电再上电，做一次自检，确认零点掉电保持。

#### 4.8.4 部分失败与恢复

| 情况 | 处理 |
|---|---|
| 回读 `\|raw\| < 2°` | 成功 |
| 回读 `raw ≈ raw_before` | 没写进去，清 pending，可安全重试 |
| 回读超时/不确定 | 保留 pending，禁止运动；下次上电先读 raw 再判断 |
| 部分电机失败 | 成功的保持 raw=0，失败的保留旧 raw；进维护态，只允许重试归零 |
| 全部成功 | 建议断电再上电自检 |

- 没有“撤销”：只能在正确参考姿态重新归零。
- pending 存证保证中途掉电也能判断每台电机的状态。

#### 4.8.5 与录制/回放的关系

- 录制/回放**不要求每次都归零**；它们只做 4.9.1 的 ±15° raw 门禁。
- 首次使用或换臂后需要归零一次；之后只要 raw 在 ±15° 内，
  录制/回放不再需要写电机 flash。
- 归零只在两种场景做：
  1. 换了另一条机械臂（或换了电机）；
  2. 发现 16 个 raw 明显不在参考姿态附近、且确认是换臂导致。
- 普通录制/回放：把手臂摆到参考姿态即可，不需要写零。

#### 4.8.6 夹爪

- 夹爪和臂关节一样参与归零，写零后 raw=0。
- 录制/回放直接存/发夹爪 raw，不做开度换算。
- 起点门禁对夹爪同样判 `|raw| ≤ 15°`；15° 只占夹爪约 360° 行程的 4%，
  如果不希望夹爪卡这么死，可单独把夹爪门限放宽（设置页可配）。

### 4.9 动作录制（需求 8）

#### 4.9.1 姿态门禁（录制/回放共用）

录制/回放是 raw 对 raw，不需要 offset/标定；唯一的约束是**起始姿态一致**。
所以进入前统一做一次门禁：

```text
读取 16 个轴的 raw（14 臂 + 2 夹爪）
要求：
  1. 全部在线、无 NaN
  2. 所有 |raw| ≤ 15°（0.2618 rad）
  3. 姿态稳定：最近 500 ms 内 |v| < 0.05 rad/s（或 raw 变化 < 0.5°）
任一不满足 → 拒绝开始，屏幕指出超差轴 + 当前角度，
并提示：“请把机械臂摆到参考姿态（±15°）；如果是刚换过臂，先执行归零”
```

- 门禁阈值默认 15°，可在设置页改（建议 10~20°）。
- 夹爪也参与门禁：归零后 raw=0，同样判 ±15°。
  15° 只占夹爪约 360° 行程的 4%，如果觉得太紧，可单独放宽夹爪门限。
- 提示语给两条路：① 摆到参考姿态；② 换臂后先做 4.8 归零。
- 录制时允许用户先在零力矩/重力拖动模式下把手臂摆到参考姿态，
  再按“开始录制”；此时才做门禁检查。
- 回放在进入 CSP 之前做门禁；不通过就不进 CSP（避免绝对目标跳变）。

> 这条门禁是录制/回放与归零之间**唯一**的联系。
> 正常录制/回放不需要归零；归零只在换臂/换电机时做（见 4.8）。

#### 4.9.2 流程

```text
选择拖动方式（零力矩 / 重力补偿）
  → 进入拖动模式（电机使能，按 4.4 的控制律）
  → 把机械臂摆到参考姿态（16 轴 raw 都在 ±15°）
  → 按 OK 开始 → 姿态门禁检查
  → 通过后以 100 Hz 采样 raw[16]（电机原始位置）
  → 按 OK 停止
  → 选择槽位 1~5 → 保存（写 W25Q64）
```

#### 4.9.3 关键设计

- 采样与控制在同一个 10 ms 周期，记录的是**反馈 raw 位置**（不是指令）。
- 帧格式用 int16 定点：`scale = 2500 counts/rad`，覆盖 **±13.1 rad（略大于 ±4π）**，
  分辨率 0.0004 rad（≈0.023°）。不能沿用 8000（只能覆盖 ±4.09 rad，
  夹爪/多圈会溢出）。
- 16 轴 × 2 B = 32 B/帧，100 Hz = 3.2 KB/s。
- 录制时 `control_slot` 只把一帧推进 RAM 环；`storage_slice` 攒满 4 KB 扇区后
  启动一次写 flash。
- **flash 擦/写不阻塞控制**：先用 RAM 双扇区缓冲，发擦除/写命令后立即返回，
  下一圈 `storage_slice` 只查一次 `BUSY`；芯片内部忙的时间不占 CPU。
- 掉电保护：每写一个扇区更新头部的 `frame_count` 和 CRC；上电扫描时
  以最后一个完整扇区为准，丢弃半帧。
- 单条最长按槽位容量限制（见 5.1），UI 显示剩余时间。

#### 录制时的安全

- 零力矩拖动：Kd=0，手臂完全自由，注意坠落；建议两人操作。
- 重力补偿拖动：Kd>0，残余漂移可接受；夹爪不补偿。
- 录制中急停/故障：立即停止录制，保留已写扇区，标记“未完成”。
- 不允许在 CSP 模式下录制（CSP 不能松劲）。

### 4.10 回放（需求 9）

#### 进入

```text
选槽位 → 显示时长/帧数
  → 姿态门禁（4.9.1，16 轴 |raw| ≤ 15°）
  → 设置间隔（速度）与次数
  → 确认 → 预对准 → CSP 回放
```

- 门禁不通过 → **拒绝回放**，指出超差轴并提示摆正；
  用户可以先进零力矩/重力拖动模式把手臂摆到参考姿态，再回来重试。
- 门禁通过后还要检查首帧 `raw` 是否在协议量程 ±4π 内，防止录制数据损坏。
- 回放直接把录制的 `raw` 写进 CSP `loc_ref`，**不做任何坐标换算/offset 补偿**；
  门禁保证起点与录制时一致，这是录制/回放与归零解耦的关键。

#### 预对准

CSP 的 `loc_ref` 是绝对 raw 目标。虽然门禁已经把当前姿态限制在参考姿态
±15°、录制也从参考姿态开始，但仍要做一次平滑过渡，避免第一帧直接跳：

- 先进入 CSP，第一帧 `loc_ref` 写**当前实测 raw 位置**；
- 用 `limit_spd` 限制速度，从当前 `loc_ref` 线性插值到首帧，
  持续 1~2 s（可配置）；
- 到位后再开始按时间轴回放。
- 如果门禁/量程校验失败，不做预对准，直接拒绝。

#### 回放

- 控制周期 100 Hz；帧间隔 `interval_ms` 可调（例如 10~100 ms/帧），
  即“慢放/快放”；默认 10 ms。
- 帧间线性插值，保证 CSP 目标连续。
- 每次循环结束可停在末帧或回到首帧（配置）。
- 次数 1~99 或无限；急停/任意键立即中止 → 保持当前位置（CSP HOLD），
  不失能（避免坠落），再让用户选择退出。
- 回放前校验每帧 `raw` 在 ±4π 内；可选再与录制头里记录的 min/max 对比，
  越界则拒绝并指出轴/帧号。
- 回放期间显示进度条、循环计数、当前帧号。

#### 为什么用 CSP

- 位置精度高、通信丢帧也不会跑飞（位置环在电机里）。
- 回放不需要每拍算力矩，CPU 负担低。
- 代价：不能柔顺；回放前必须确认路径无障碍。

### 4.11 参数与持久化

#### 板端可写参数

| 参数 | 作用 | 写入位置 |
|---|---|---|
| `run_mode` | MIT/CSP | 电机 RAM（0x7005），每次上电/切换重写 |
| `max_torque`（逐轴） | MIT 软件钳位 + CSP 折算 `limit_cur` | 板端配置 + `0x700B`/`0x7018` |
| `max_speed`（逐轴） | MIT 钳 `v_des`；CSP 写 `limit_spd` | 板端配置 + `0x7017` |
| `acc_rad` | CSP 加速度 | 板端配置 + `0x7022` |
| `Kp/Kd`（保持） | MIT HOLD | 板端配置 |
| `Kd_drag` | 重力拖动阻尼 | 板端配置 |
| `gravity_ratio` | 0~1 手感 | 板端配置 |
| `playback interval/loops` | 回放 | 板端配置 |
| 夹爪策略 | 自动/强制 | 板端配置 |

- **不写类型 22**（会固化所有参数，包含残留 run_mode）。
- 参数改动后立即重写对应 RAM 寄存器；掉电后由板端配置恢复。

#### 24C02 vs W25Q64 分工

- **24C02（256 B）**：用户设置（压缩结构 + CRC），掉电快速恢复；
- **W25Q64**：归零记录/pending、轨迹、字库、黑匣子。没有“标定偏移”要存，
  因为录制/回放全用 raw。

### 4.12 安全与故障

| 机制 | 行为 |
|---|---|
| IWDG | 2 s 超时；主循环喂狗；`control_slot` 心跳丢失 → 复位 |
| 控制周期抖动 | > 2 ms 记录；> 20 ms 触发降级 |
| 反馈超时 | 单关节 > 200 ms 无 type-2 → 该关节写 0 + 报故障；整臂 > 500 ms → 全失能 |
| 故障位 | 欠压/栅极/过温/编码器/堵转/未标定 → 显示 + 按等级降级（过温/堵转直接失能该臂） |
| 过温 | 温度 > 75 °C 告警，> 85 °C 失能 |
| CAN bus-off | 自动恢复；连续 3 次 → 锁存故障 |
| 急停 | **硬件切断电机动力** + 软件全失能；锁存，人工复位 |
| 急停恢复 | 电机已断电重启 → **重新探测、重写 run_mode/limit_*、重新使能**，不能直接续跑 |
| 位置读不到 | HOLD 拒绝激活；运行中退化为全 0 松劲 |
| 归零 | 必须先失能；写后验证 \|raw\|<2°；16 轴含夹爪；无 offset |
| 回放 | 限位校验、速度限制、任意键中止 |
| 看门狗复位后 | 电机保持最后命令（MIT）→ 上电默认先发全 0/失能 |

> ⚠️ MIT 模式下通信断了电机会保持上一帧，可能一直出力。因此：
> - 板端必须有“命令超时 → 全 0”兜底；
> - 硬件急停直接切断电机动力（已确认），但要注意**断电后机械臂会因重力下落**；
>   若结构不允许，需加抱闸或分级急停。

## 5. 存储布局

### 5.1 W25Q64（8 MB，4 KB 扇区）

| 地址范围 | 大小 | 用途 |
|---|---|---|
| `0x000000–0x00FFFF` | 64 KB | 配置/归零记录 A/B 双份 + 版本 + CRC |
| `0x010000–0x01FFFF` | 64 KB | 中文字库子集 + 图标 |
| `0x020000–0x02FFFF` | 64 KB | 归零 pending 记录 + 出厂参数/日志头 |
| `0x030000–0x7AFFFF` | 7.5 MB | **5 个动作槽，每槽 1.5 MB** |
| `0x7B0000–0x7FFFFF` | 320 KB | 黑匣子环形日志 |

单槽 1.5 MB / 32 B = 49152 帧 = **491 s @100 Hz**（约 8 分钟）；
5 条动作总容量约 40 分钟，远超“5 条以内”的需求。

### 5.2 轨迹格式

```c
#define TRAJ_MAGIC 0x4A52544C  // "LTRJ"

typedef struct __attribute__((packed)) {
  uint32_t magic;
  uint16_t version;       // 1
  uint16_t joint_count;   // 14 / 16（轴数）
  uint16_t sample_ms;     // 10
  uint16_t flags;         // bit0: 含夹爪；bit1: 录制完成
  uint32_t frame_count;
  int16_t  scale;         // 2500 counts/rad（覆盖 ±4π）
  uint16_t reserved;
  uint32_t crc32;         // 覆盖头部之后的数据
  char     name[16];      // UTF-8/ASCII 槽名
  uint32_t reserved2;
} traj_header_t;          // 44 B（按 4 KB 扇区对齐写，不要求 2 的幂）
```

- 数据区从槽起始 + 4 KB 开始（头部单独一个扇区）。
- 每帧 `int16 raw[16]`（电机原始位置，小端），不做任何坐标变换。
- 槽位写入顺序：先擦头扇区 → 写头（`flags` 未完成）→ 逐扇区写数据 →
  最后更新头（`flags` 完成 + CRC）。
- 上电扫描：magic/CRC 对且 `flags` 完成才算有效。

### 5.3 24C02（256 B）

| 偏移 | 大小 | 内容 |
|---|---|---|
| 0x00 | 16 B | magic/version/长度/CRC |
| 0x10 | 96 B | 设置 A（协议、默认模式、Kp/Kd、重力比例、回放参数、夹爪策略、语言…） |
| 0x70 | 96 B | 设置 B（A 的镜像） |
| 0xD0 | 16 B | 归零记录版本/CRC/预留 |
| 0xE0 | 32 B | 预留 |

- 逐轴的 torque/speed 上限如果放不下，就放 W25Q64 配置区，
  24C02 只存全局设置；启动时先读 24C02 再读 W25Q64 合并。
- 24C02 页写入 8 B，注意跨页；写后延时 5 ms。

## 6. 关键风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| direction 错（仅重力补偿用） | 重力前馈方向反、手臂被推走 | 逐轴对照 ROS 的 direction；先在台架验证；不参与录制/回放 |
| 换臂后未归零 | 两臂 raw 零点差大，使能/回放时冲向零位 | 换臂后强制归零；上电/使能前检查 \|raw\|；归零后 raw=0 |
| 归零姿态偏差（用户手动摆） | raw 基准偏，重力/换臂统一受影响 | 同一臂录制/回放仍自洽；屏幕显示 16 轴 raw；建议参考姿态做标记 |
| 类型 6 部分失败 | 部分电机已归零、部分未归零 | pending 存证 + 逐台验证；失败进维护态，只允许重试 |
| 录制/回放起点不在 ±15° | 轨迹起点不一致、回放跳变 | 4.9.1 姿态门禁；拒绝并指出超差轴 |
| 无夹爪误开重力拖动 | 手臂上飘、无法静止 | 检测到 14 轴**默认关闭重力补偿**；后续补无夹爪标定 |
| 硬件急停断电 | 机械臂因重力下落 | 加抱闸，或改分级急停（先受控停止再断动力）；结构上评估 |
| CSP 切换时仍使能 | 电机跳变/故障 | 先失能、等 50~100 ms、再写 run_mode、斜坡使能 |
| CSP 写 0 当松劲 | 机械臂冲向零点 | 代码层禁止 CSP 零力矩路径；回放/保持才进 CSP |
| 参数写入 RAM 掉电丢失 | 上电行为不符 | 每次上电/模式切换重写；不从电机 flash 读 |
| kt 折算漏 √2 | 力矩只有 70.7% | 单测钉住公式；显示折算后 Apk |
| 主循环被 flash/UI 阻塞 | 控制周期抖动/丢帧 | 非阻塞状态机 + 双扇区缓冲 + 时间片预算（3.5） |
| CAN 突发撑爆邮箱 | 使能帧丢、电机不动 | 发送队列节流 2~3 帧/ms；使能与参数分两趟 |
| 中文全字库太大 | Flash/RAM 不够 | 子集字库 + 放 W25Q64 + 按需读 |
| LVGL 全屏刷新太慢 | UI 卡顿 | 部分缓冲 + 脏区刷新 + DMA |
| 电源/地/终端电阻 | 通信偶发错误 | 双绞线、120 Ω 端接、共地、隔离收发器（建议） |
| 夹爪归零后门禁太紧 | 15° 只占夹爪约 360° 行程的 4% | 夹爪门限可单独放宽（设置页） |
| 重力模型 float 精度 | 力矩偏差 | 已验证 double 公式；float 误差 < 1e-4 N·m；输出再钳位 |
| raw 超出 ±4π | 录制/回放位置越界 | 录制/回放都钳在 ±4π；回放前校验 |

## 7. 开发里程碑

| 阶段 | 内容 | 验收 |
|---|---|---|
| **M0** 工程骨架 | CubeMX 时钟/引脚、1 ms SysTick 调度骨架、UART 日志、IWDG、主机侧单测框架 | 串口打印版本；协议单测通过 |
| **M1** BSP | ST7789 点亮、按键消抖、W25Q64/24C02 读写、蜂鸣器 | 屏幕显示自检页；EEPROM/Flash 读写校验 |
| **M2** 协议与单总线 | C 版协议、CAN1 探测、读位置、使能/失能、零力矩 | 与 ROS `set_zero --check` 的 raw 值一致；帧逐字节一致 |
| **M3** 双总线与 MIT | 14/16 轴、raw 读写、HOLD/斜坡、故障/超时 | 手动推拉有阻尼；掉线自动松劲 |
| **M4** 重力拖动 | 生成模型、主机验证、板端运行 | 任意姿态可单手拖动；松手漂移 < 1°/3 s；与 ROS 前馈值对照 < 0.01 N·m |
| **M5** CSP 与回放 | 协议切换、CSP HOLD、±15° 门禁、预对准、5 槽回放 | 超差时拒绝并提示；回放跟踪误差 < 0.02 rad；任意键中止不坠臂 |
| **M6** 录制与 UI | 两种拖动录制、±15° 门禁、落盘、槽位管理、设置页、类型 6 归零（pending/部分失败/回读不确定处理） | 断电后轨迹完整；5 条可选；归零回读 < 2°；部分失败可重试 |
| **M7** 整机与安全 | 急停、黑匣子、长稳、文档 | 连续 1 h 无 CAN 错误；故障注入可安全降级 |

预计 4~6 周（1 人，含真机调试）。M4 和 M6 是风险最高的两段。

## 8. 已确认决策与剩余待确认项

### 8.1 已确认（v1.0）

| 项 | 决策 |
|---|---|
| 坐标空间 | 录制/回放/归零/门禁**全部用 raw**；不需要 homing_offset/限位/夹爪端点 |
| 整机归零 | 用户自己摆参考姿态，**16 台电机（含夹爪）**写类型 6，写后 raw=0 |
| 录制/回放 | 16 轴 raw 门禁 ±15°，不合格拒绝；与归零解耦 |
| 重力补偿 | **保留**；`direction` 从 `calibration.yaml` 固化 16 个 ±1 |
| 标定表 | **不做运行期导入**；固件只带静态电机表 |
| 调度方式 | **裸机 + 1 ms 协作式调度**，不用 RTOS |
| 无夹爪方案 | 暂只做 16 轴完整方案；14 轴只探测 + 基础控制，重力补偿关闭 |
| 板子定位 | 完全独立，不接 ROS |
| UI/按键 | 中文 + 4 键（上/下/OK/BACK） |
| 硬件安全 | 硬件急停切断电机动力 |

### 8.2 P0（还需要确认，未定会影响安全/结构）

1. **direction 符号核对**：按 `calibration.yaml` 固化 16 个 ±1 没问题，
   但要在台架上逐轴确认“正方向/力矩符号”与实机一致（尤其夹爪）。
2. **参考姿态显示**：用户自己摆，板子只显示 16 轴 raw 角度供核对，
   这样做够吗？还是需要别的辅助（比如每个轴单独显示/蜂鸣提示）？
3. **换臂场景**：同一块板子会经常换不同机械臂吗？
   如果基本不换，归零可以只在首次调试时做一次，甚至做成隐藏功能。
4. **已画好的板**：提供原理图/引脚表，用于核对 `board_config.h`；
   另外确认动力电压/电流，用于急停接触器/线束选型。
5. **急停断电后机械臂下落能否接受**？如果不能，需要抱闸或分级急停
   （先受控停止、延时再断动力），这会改变安全回路设计。
6. **夹爪 ±15° 门禁是否太紧**？15° 只占夹爪约 360° 行程的 4%，
   建议夹爪单独用 30~45° 或按行程百分比；你倾向哪种？

### 8.3 P1（影响体验/容量）

7. 固件栈确认：裸机 + 1 ms 协作式调度 + LVGL 8.3 + STM32CubeIDE(HAL)
   可以接受吗？（不引入 RTOS）
8. 录制规格：100 Hz 采样可以吗？单条最长需要多久？5 条固定还是可配置？
   是否需要掉电保护？
9. 回放起始：允许自动平滑预对准（1~2 s），还是要求手动摆到首帧附近？
   回放中要不要暂停/单步？
10. MIT 最大速度：MIT 没有速度寄存器，接受“软件钳 `v_des`”吗？
    力矩上限写 `0x700B` 还是只写 `0x7018`（或两者都写）？
11. 夹爪检测：只探 ID 18/28 可以吗？单侧缺失怎么处理？臂轴缺失是否
    一律禁止使能？
12. 屏幕确认：1.54" 240×240、无触摸、SPI、3.3 V。
13. 4 键定义确认：UP / DOWN / OK / BACK 可以吗？是否需要再加一个独立
    STOP 键（不经过菜单，直接全失能）？

### 8.4 P2（后续增强）

14. 是否需要黑匣子（故障前 N 秒的 raw/CAN 记录）？
15. 是否需要蜂鸣器/LED/风扇/母线电压监测？
16. 固件升级方式：SWD / USB DFU / SD？
17. 机械臂基座安装是否与 URDF 一致（水平/倾斜）？重力方向要不要可配置？
18. 电机固件版本？是否支持类型 22、`0x700B` 等参数？
19. 轴名称/ID/型号是否与 `joint_spec.yaml` 完全一致？有没有左右臂差异？
20. 是否需要在板端显示/记录电池电量、电流？
