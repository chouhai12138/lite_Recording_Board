# 重力补偿移植说明（精确解析式，STM32F407）

> 目标：把 `/data/lite_motor_ws` 里 `lite_controller/gravity_compensator.cpp`
> 的 **pinocchio `rnea(q,0,0)` 重力前馈**原样搬到 STM32，得到一个
> **独立、可直接引用、无 pinocchio、无动态内存**的 C 模块。
>
> 结论：已实现，`Tests/test_gravity.c` 与 pinocchio 参考在 200 组随机位形上
> **max_err = 7.0e-5 N·m**（float 核心，含 raw→q 的 homing_offset 映射与
> 多圈折算）；固件 Flash 增量约 **9 KB**。

---

## 1. 文件清单

### 独立可复用的最小集合（拷这 4 个就能用）

| 文件 | 作用 |
|---|---|
| `App/control/gravity.h` | 公共 API（`Gravity_TorqueF` / `Gravity_TorqueRawF`） |
| `App/control/gravity.c` | 精确解析重力矩（FK + 重力投影），只依赖 `<math.h>` |
| `App/cfg/gravity_model.h` | 自动生成的链常量 + 惯性参数 + offset（`static const`） |
| `App/cfg/joint_map.h` | **raw→q 固定映射**：direction / homing_offset / 关节区间 |

把它拷到任何 Cortex-M 工程，`-I` 指到这两个目录，加入 `gravity.c`，
链接 `-lm` 即可。示例：

```c
#include "gravity.h"

float raw7[GRAV_DOF] = { /* 7 个电机 raw 位置 */ };
float tau[GRAV_DOF];
Gravity_TorqueRawF(0, raw7, tau);   /* 0 = 左臂, 1 = 右臂 */
```

API 约定：

- `q` 顺序 = `shoulder_pitch, shoulder_roll, shoulder_yaw, elbow_pitch,
  wrist_yaw, wrist_roll, wrist_pitch`（与电机 0..6 / 8..14 一致）。
- `Gravity_TorqueF` 输出**关节空间** `τ_q`（N·m，已含每关节 `offsets_nm`）；
  送 MIT 前请用 raw 版，不要直接下发。
- `side` 只用 0/1；越界会读另一侧表（调用方保证）。
- 板端 **raw 版** `Gravity_TorqueRawF(side, raw, tau_raw)`：
  输入电机原始位置，内部按 `joint_map.h` 做
  `q = direction·(raw − homing_offset) + k·2π`，算完再
  `τ_raw = direction·τ_q`。`Gravity_TorqueF` 仍收关节角 `q`（主机测试用）。

> ⚠️ **不要**把 `MotorMgr` 的 `m->pos`（raw）直接喂给 `Gravity_TorqueF`。
> 左右臂分别有 5 / 3 个关节 `direction = -1`，直接喂会让这些关节的
> 重力矩反号；即使补上 direction，**还差 homing_offset**——模板机
> raw=0（自然下垂归零）时肩 roll 的 q 约为 ∓89.5°，直接当 q=0 会差
> **6 N·m 级**。DRAG 前馈必须用 `Gravity_TorqueRawF`。

### 生成与验证（工作区内，便于复现）

| 文件 | 作用 |
|---|---|
| `Scripts/gen_gravity_model.py` | 从 URDF + `inertia_params.yaml` 生成 C 表与参考 |
| `Scripts/gen_joint_map.py` | 从 `calibration.yaml` + `joint_spec.yaml` 生成 raw→q 映射 |
| `Scripts/model/lite_arm_model.urdf` | 纯 URDF（pinocchio 可直接加载） |
| `Scripts/model/inertia_params.yaml` | 重力辨识结果（与 lite_motor_ws 同步） |
| `Scripts/model/calibration.yaml` | 模板机 homing_offset / direction |
| `Scripts/model/joint_spec.yaml` | 关节上下限（仅用于整圈折算） |
| `Tests/test_gravity.c` | 主机 gcc 单测：C 实现 vs pinocchio 参考（含 raw+多圈路径） |
| `Tests/gravity_ref.h` | 200 组随机位形的 `rnea(q,0,0)+offset` 参考 |

## 2. 算法

对转动关节 `k`（重力只与质量/一阶矩有关，惯量张量无关）：

```
τ_k = −(R_k·a_k) · Σ_{i∈distal(k)} [ (p_i − p_k)×(m_i·g) + (R_i·m_i·c_i)×g ]
      + offset_k
```

- `R_i, p_i`：第 i 段关节系的世界姿态/位置（正运动学）。
- `a_k`：关节轴（关节系）。
- `m_i`：质量；`m_i·c_i`：关节系一阶矩（即 YAML 的 `first_moment`）。
- `g = (0, 0, −9.81)`。
- `distal(k)`：k 的所有后代段（含自身）——用生成期算好的位掩码 `desc`，
  运行期只做位测试。

正运动学（串行链）：

```
R_i = R_parent · R0_i · R_axis(a_i, q_i)
p_i = p_parent + R_parent · t_i
```

夹爪两根手指是 `wrist_pitch` 的**兄弟固定段**（prismatic，q=0），
不是串在腕后面的；生成器按 `model.parents` 建立 `parent` 指针，
运行期自然支持这种分支。

## 3. 参数约定的四条铁律（生成器已内建）

1. **按连杆名索引**，不按下标：生成期用 `model.getJointId(name)`。
2. **mass 与 first_moment 成对使用**：两者一起写回模型，不能单独解读。
3. **`mass: null` 取 1.0，但一阶矩照常参与**：
   旧 `gen_gravity_model.py` 在 `m=0` 时把 `mc` 也清零，丢掉肩 pitch 的
   `my/mz`，这是之前近端关节误差大的主因之一。
4. **`offsets_nm` 必须加**：生成期写入 `kGravOffsetLeft/Right`。

> 注意：`first_moment` 就在 pinocchio 关节系，**不要**再乘/除 g，
> **不要**叠加 URDF `<inertial><origin>` 的旋转。
>
> 板端坐标：模型在 URDF 关节空间，电机在 raw 空间。`joint_map.h` 固化
> 每关节的 `direction`、`homing_offset` 与关节区间：
>
> ```
> q_i     = direction_i · (raw_i − homing_offset_i) + k_i·2π
> τ_raw_i = direction_i · τ_q_i
> ```
>
> `homing_offset` 来自模板机的 `calibration.yaml`（自然下垂归零时
> raw=0 对应 q_hang，肩 roll 约 ∓89.5°）。`k_i` 取"离关节区间中点
> 最近的一圈"，用于抵消电机多圈。**这两个都不能省。**

## 4. 重新生成（换标定/URDF 后）

```bash
cd /data/stm32_ws/stm32_lite_Recording_Board
source /data/lite_dynamics_calib/env.sh

# 1) 同步最新标定（可选：直接把 lite_motor_ws 的文件拷过来）
cp /data/lite_motor_ws/src/lite_controller/config/gravity/lite_arm_model.urdf   Scripts/model/
cp /data/lite_motor_ws/src/lite_controller/config/gravity/inertia_params.yaml   Scripts/model/
cp /data/lite_motor_ws/src/lite_controller/config/gravity/joint_spec.yaml       Scripts/model/
cp /data/lite_motor_ws/src/lite_calibration/config/calibration.yaml              Scripts/model/

# 2) 生成 App/cfg/gravity_model.h + Tests/gravity_ref.h
python3 Scripts/gen_gravity_model.py
#   会先自检：解析式 vs pinocchio rnea，要求 < 1e-9 N·m，否则拒绝生成

# 3) 生成 App/cfg/joint_map.h（换机器人 / 重新归零后必须更新）
python3 Scripts/gen_joint_map.py

# 4) 主机验证 + 固件编译
make test
make
```

生成器会打印：

```
自检：解析式 vs pinocchio rnea 最大差 = 2.665e-14 N·m
生成：App/cfg/gravity_model.h（9 段/侧）
生成：Tests/gravity_ref.h（200 组）
生成：App/cfg/joint_map.h（7 关节/侧）
```

## 5. 验证结果

```
$ make test
gravity: 200 samples, max_err=7.026e-05 N·m (tol 1e-03), failures=0
```

- 解析式（Python 版）vs pinocchio `rnea`：**2.7e-14 N·m**（生成器自检）。
- C 实现（float）vs pinocchio（double）：**7.0e-5 N·m**，来自 float 舍入；
  关节空间 `Gravity_TorqueF`、raw 空间 `Gravity_TorqueRawF`（含
  `homing_offset`）以及"raw + 2π 多圈"三条路径在 `Tests/test_gravity.c`
  里都做了对照。
- 标定本身的 holdout RMSE ≈ 0.09 N·m，因此 float 误差完全可忽略。

> 旧方案（`gravity_fit.h` 基函数拟合）max_err ≈ 1.3 N·m，已弃用；
> `App/cfg/gravity_fit.h` 不再被包含，`Scripts/fit_gravity.py` 仅作对照保留。

## 6. 资源与实时性

- 模型表：每侧 9 段 ×（9+3+3+1+3+3）≈ 22 float ≈ 88 B，两侧 ~1.4 KB；
  `joint_map.h` 再 ~0.3 KB，加上代码 Flash 增量约 **9 KB**。
- 固件整体：Flash **92.8 KB / 512 KB（17.7%）**，RAM 16.96 KB / 128 KB（13.2%）。
- 运行期：每侧一次 9 段 FK（7 转动 + 2 夹爪固定）+ 7×9 次力矩累加，**无 malloc、无文件 I/O**；
  float 走 F407 单精度 FPU。100 Hz 下占用远小于 1 ms（可忽略）。
- `mit_ctrl.c` 已改为**每拍每侧只算一次**（旧代码在每个电机循环里重复算 14 次）。

## 7. 集成点

`App/control/mit_ctrl.c` 的 `MIT_MODE_DRAG`：

```c
#if GRAVITY_FF_ENABLE
float raw_l[GRAV_DOF], raw_r[GRAV_DOF];
float tau_l[GRAV_DOF], tau_r[GRAV_DOF];
/* 每拍每侧算一次：raw 来自 MotorMgr，内部按 joint_map 转 q / 转回 raw */
for (k = 0; k < GRAV_DOF; k++) { raw_l[k] = (float)m[k].pos; }
for (k = 0; k < GRAV_DOF; k++) { raw_r[k] = (float)m[8 + k].pos; }
Gravity_TorqueRawF(0, raw_l, tau_l);
Gravity_TorqueRawF(1, raw_r, tau_r);
#endif
...
case MIT_MODE_DRAG:
    kp = 0.0;
    kd = 0.5;
#if GRAVITY_FF_ENABLE
    if (i < 7U) {
        trq = tau_l[i];
    } else if (i >= 8U && i < 15U) {
        trq = tau_r[i - 8U];
    }
#endif
    break;
```

> `tau_l/tau_r` 已经是 **raw 空间**，可直接写进 MIT 帧，不需要再乘 direction。
> 若调用方只有关节角（离线工具），继续用 `Gravity_TorqueF`，不要混用。

⚠️ **电机表下标**（与 `MotorMgr_Init` 一致，**右臂不是从 7 开始**）：

| idx | 0..6 | 7 | 8..14 | 15 |
|---|---|---|---|---|
| 电机 ID | 11..17 | 18 | 21..27 | 28 |
| 含义 | 左臂 7 关节 | 左夹爪 | 右臂 7 关节 | 右夹爪 |

`App/control/mit_ctrl.c` 用 `ARM_LEFT_IDX0=0`、`ARM_RIGHT_IDX0=8`、
`ARM_JOINTS_PER=7` 三个宏表达，避免把右臂力矩错加到左夹爪上。

`GRAVITY_FF_ENABLE` 在 `mit_ctrl.c` 顶部默认 1。需要 A/B 对照时改成 0 重编译。

## 8. 已知限制

- 只补偿**臂关节 7 个/侧**；夹爪两段按 **q=0** 参与远端力矩（与离线
  `gravity_compensator.cpp` 冻结夹爪的约定一致）。夹爪实际开度会带来
  约 0.3 N·m 的模型差异。
- 板端 raw→q 已包含 `direction`、`homing_offset` 和 `2π` 多圈折算
  （`joint_map.h`）。`homing_offset` 是**模板机**的值；换机器人或重新归零
  后必须重新生成，否则 q 会整体偏。
- 模型只含准静态重力；摩擦/惯量/科氏力未建模。
- `GRAV_G` 固定 9.81；若标定侧改用其它重力常数，需同步。
- **MIT 力矩编码必须按每轴型号量程**：`rs-02` 17 N·m、`rs-00` 14 N·m、
  `rs-05` 5.5 N·m。旧 `MotorMgr` 统一按 `rs-02` 编码，rs-05 轴的实际力矩
  只有 `5.5/17 ≈ 0.32` 倍，重力前馈会明显偏弱（腕关节最明显）。
  现已改为 `limits_for_id()` 按 CAN ID 取型号；`gen_robot_config.py`
  落地后可改为生成表。
- `mit_ctrl.c` 的整机安全钳位当前为 **±12 N·m**（A5 原为 ±5，肩关节
  极端姿态重力矩 ~7.5 N·m 会被削）；如需按 `max_safe_torque` 逐轴钳位，
  等 `robot_config` 生成后替换。
