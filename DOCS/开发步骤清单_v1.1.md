## 0. 现状盘点

### 0.1 目标（文档已定）

独立板（不接 ROS）：双 CAN、4 键、ST7789 240×240、W25Q64、24C02、硬件急停；
功能 = MIT/CSP 控制、重力补偿拖动、动作录制/回放（5 槽）、16 轴归零。
裸机 + 1 ms 协作式调度，坐标空间全部用电机 raw。

### 0.4 必须先解决的差异（**重要**）

1. **引脚冲突**：文档 v0 把 PB13/14/15 分给了 W25Q64 的 SPI2（SCK/MISO/MOSI），
   按键在 PE0~PE3。实际板子 PB13/14/15 + PD11 是**按键**，PE0~PE3 是否还在未知。
   → 底板到货后按新原理图重定外设引脚，`board_config.h` 是唯一改动点。
2. **按键语义**：文档假设 4 键 = 上/下/OK/BACK（**无左右**，纵向列表）；
   实际是 上/下/左/右。建议映射：**左 = 返回(BACK)，右 = 确认(OK)**，
   这样既保留文档的“纵向列表”交互，又不浪费左右键（可做页内快切）。
3. **4 个 LED 定位**：PA15 / PD15 / PD12 / PD13。建议语义：
   `PA15=RUN(心跳)`、`PD15=CAN/总线状态`、`PD12=REC(录制中)`、`PD13=FAULT`。

## 1. 目录结构（落地版，对齐文档 3.7）

```
stm32_lite_Recording_Board/
├── Core/            # 已有：时钟/中断/printf 重定向/链接脚本
├── BSP/             # 已有：led/uart；待加 keys、buzzer、power
├── App/
│   ├── app_sched.c/h        # 1 ms 协作调度（时间片表）
│   ├── app_state.c/h        # 模式状态机
│   ├── cfg/                 # robot_config.c/h、gravity_model_*.c/h（脚本生成）
│   ├── motor/               # rs_protocol、can_bus、motor_mgr、joint_map
│   ├── control/             # mit_ctrl、csp_ctrl、gravity、safety
│   ├── motion/              # recorder、playback、traj_store
│   └── ui/                  # ui_core（页面/导航）+ ui_text（串口后端）
├── Sim/                     # ★ 新增：虚拟 CAN 总线 + 16 台假电机
├── Scripts/                 # gen_robot_config.py、gen_gravity_model.py
├── Tests/                   # 主机侧 gcc 单测：test_protocol.c、test_gravity.c
└── DOCS/
```

关键设计：**UI 与存储都做成后端可替换**
（`ui_backend`：text→串口 / lvgl→ST7789；`traj_store`：RAM / W25Q64），
这样底板没到也能把 90% 的固件写完、测完。

## 4. 已确认（v1.1 落地）

- 按键语义：**LEFT = 返回、RIGHT = 确认**（UP/DOWN 选择）
- LED 极性：4 路均为**低电平点亮**；`PA15=RUN / PD15=CAN / PD12=REC / PD13=FAULT`
- 16 轴参数来源：`lite_controller/config/gravity/joint_spec.yaml` + `lite_calibration/config/calibration.yaml`
